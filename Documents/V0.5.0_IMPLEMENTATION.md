# v0.5.0 快適性改善の実装・検証

2026-10-16（日本時間）。[実装案](V0.5.0_PLAN.md)の採用指示と「フォトの実機テストはユーザーが手動で行う」という指定に基づく。

## 実装範囲

- ロードをImages/updateButton.pngの埋込みアイコンへ変更。文字のアクセシブル名、ツールチップ、キーボード操作・無効表示を保持し、アドレス欄を拡張した。
- フォルダー選択ダイアログは入力中の有効なアドレスを開始位置へ設定。無効なら現在のフォルダー、いずれも無効ならOSの既定位置へ戻す。選択のキャンセルで閲覧位置は変更しない。
- ヘルプの版表示と更新確認を［更新確認］へ統合。非同期確認後に、アプリアイコン・使用版・確認日時・新版の有無／失敗・更新履歴リンク・最新版取得を含む独立ダイアログを表示する。通信中は閲覧を継続できる。
- 起動時は初回または確認開始から24時間経過した場合だけ確認。開始／成功日時をUTCで設定へ保存し、失敗も開始日時を残す。未来日時は再確認で修正し、壊れた日時は未確認扱い。手動確認は制限を受けず、進行中の確認は共有する。
- 起動時は新版がある場合だけ取得の可否を確認。了承後は共通ダイアログから保存先選択へ進む。編集中・保存中・モーダル中・最小化／通知領域格納中は通知を保留。新版なし・失敗は自動ダイアログを出さない。自動確認の定期タイマーは追加せず、次回起動で再判定する。
- 既存の配布ファイル選別・数値版比較・ZIP優先・容量制限・Git blobハッシュ・一時ファイル確定・既存保存先を置換しない方式を継続。アプリの自動置換・実行は行わない。非公開リポジトリの認証は未対応。
- WindowsフォトへのLaunchFileAsyncに、親フォルダー直下のPNG／JPEG／WebPを対象とするNeighboringFilesQueryを付加。関連クエリ作成に失敗しても単体起動を維持する。検索やAB_の非表示条件・アプリ内の並べ替えとは独立し、関連付けを変更しない。
- サイドプレビューは一覧ImageListからの転用を廃止し、選択直後は余白を付ける前のキャッシュを仮表示、読込み後は長辺最大1,024pxの選択画像専用ピクセルへ置換。一覧の拡縮・後着サムネイル・テーマ切替で小さい画像へ戻さない。選択／原本／フォルダーの世代判定を維持する。
- ［ファイル名省略］は初期OFF、保存して復元。ONでは画像名を隠して文字行の高さを除き、フォルダー名はアイコン内へ表示する。元の名前をListViewに保持して支援技術の識別へ利用し、ツールチップには完全名と読込み失敗を表示。元パス・選択・検索・並べ替えは変更しない。

## 検証

- Debug／Release x64のビルド、全自己・UI試験、各3回の即時終了試験はともに成功（終了コード0）。両EXEのFileVersion 0.5.0.0とOriginalFilenameの版付きファイル名も確認した。
- 追加の合成試験で、24時間直前／一致／超過・初回／時計巻戻し、設定の旧版既定値・往復・不正日時、確認共有、手動制限除外、失敗時の成功日時保持・自動通知抑止、有効配布物なし・終了時キャンセルを確認。
- 1200×600の専用PNGで1024×512プレビューを確認。一覧幅64／256／96へ変更後も専用画像を保持。名前非表示の行間短縮・アイコン非重複・名前情報／選択／設定の保持と表示復帰、両テーマのプレビュー保持、リセットによるピクセル解放を確認。
- フォルダー選択開始位置は現在地・未確定入力優先・無効入力のフォールバックを確認。ロード素材のリソース埋込みとボタン幅を確認。v050-light.png／v050-night.png、更新確認ダイアログの画面を目視確認した。
- 試験の書込み先は各EXE配下self-test-dataのみ。通常試験の更新通信は合成データへ置換し、実GitHubへの確認／ダウンロードを行っていない。フォトの実起動試験はユーザー指定により実行していない。既存の起動先検出・失敗経路の試験は継続した。
- ログ: x64/DebugおよびReleaseのv050-build.log／v050-test.log。最初のサンドボックス内ビルドは既知のPath/PATH重複で失敗し、通常環境でビルドできた。

## 手動確認・制約

- **Windowsフォトの実機試験はユーザー担当。** 同じフォルダーに複数の画像を用意し、本アプリからフォトを開いて前後画像へ移動できるか確認する。APIへの情報設定は、フォト側の対応を保証しない。Windows／フォトの版・形式・権限による差がある旨をREADMEへ記載済み。
- 起動時の実GitHub通信・ダウンロード了承／拒否・保存先選択、通知領域からの復帰時通知、実OSの時計変更・設定書込み不可、大量フォルダー／UNCの選択開始待ち、DPI／高コントラスト、スクリーンリーダーの実操作は未検証。
- 選択プレビューは原寸表示ではない。画像ピクセルと合成キャッシュは各最大約4MiBで、デコーダー内部の作業領域・アプリ全体を含む上限ではない。OCRプレビューの入力サイズや実行条件は変更していない。
- 版付きDebug／Release EXEを作成。Stable配下のEXE・readmeと既存EXEを差し替えず、commit／push／tag／公開も行っていない。アプリ内の簡単な使い方は従来のStable文書の埋込みを継続する。
