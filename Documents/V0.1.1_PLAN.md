# v0.1.1 改修案

検討日: 2026-10-09。以下は当初の改修案。ユーザー指定の「atrl」はCtrlの意図と仮定し、同日に実装した。実装結果はUPDATELOG.mdのv0.1.1を参照。
Windowsフォトの最終方式は、実機で拒否されたActivateForFileに代えてLaunchFileAsync＋TargetApplicationPackageFamilyNameを採用。通常ユーザー環境で画像受渡し成功を確認した。目視確認は別途必要。

## ウィンドウの拡縮と画像一覧

現状はWM_SIZEで一覧の枠を再計算するが、LVS_AUTOARRANGEを指定していない。
一覧を自動整列させ、横幅の変化に応じて列数を増減する。右・左・下の各配置で一覧領域がウィンドウの余白を使用するようにする。
縮小・拡大・最大化・復元で選択を保持し、必要なら選択項目を可視位置に戻す。最小化時はレイアウト計算を省く。
領域境界をドラッグするスプリッターは今回の依頼とは別の追加候補とする。

## 一覧上のCtrl＋マウスホイール

- 初期案: 上で拡大、下で縮小。幅64〜256px、32px刻み、既定128px。サムネイルの表示枠は4:3とし、画像自体の縦横比を保持する。
- 一覧のサブクラスでCtrlとホイールを処理し、細かいデルタを累積する。Ctrlなしは一覧の通常スクロール。プレビュー上の画像切替には影響させない。
- サムネイル用ImageListとアイコン間隔を更新し、列数を再計算する。ファイル名と選択を維持する。
- サイズ変更に応じた再生成を非同期化する。フォルダー・選択とは別にサムネイルサイズの世代を持ち、旧サイズの結果を混在させない。
- 急な連続変更は短い待ち時間でまとめ、不要な再生成を減らす。元画像を毎回UIスレッドで読まない。
- サイズをsettings.jsonに追加保存する案。v0.1.0設定に項目がない場合は既定値を使用し、範囲外の数値を検証する。
- 最大サイズでのキャッシュ増大に注意し、大量画像時の上限も検討する。

## Windowsフォトの呼出し

- ダブルクリックされた項目のファイルを1回だけ渡す。現在の選択番号だけに依存せず、通知の対象項目を確認する。空白部分のダブルクリックでは起動しない。
- インストール済みMicrosoft.Windows.Photosから対象のアプリIDを取得し、IApplicationActivationManager::ActivateForFileで明示起動する方式を第一候補とする。アプリIDを未検証の固定値で決めない。
- 既定の画像アプリや関連付けは変更しない。利用不可・対象ファイル削除・起動失敗を通知し、ビューアーの操作を続けられるようにする。
- ms-photos:viewer?fileName=...も公式方式として存在するが、対象画像を開けるかと特殊文字の扱いを実機で検証してから採用判断する。
- 調査時のGet-AppxPackage -Name Microsoft.Windows.Photosは結果なし。この実行環境でパッケージを検出できなかったという範囲の結果で、ユーザーPC全体での利用不可を断定しない。フォトの起動試験は未実施。

## v0.1.1の確認項目

1. 各配置で拡大・縮小・最大化・復元すると一覧の列数が変わり、選択と表示内容が維持される。
2. Ctrl＋ホイールでサイズが上下限内で変わる。Ctrlなしのスクロール、プレビューの画像切替と競合しない。
3. サイズを高速変更しながらフォルダー変更・画像選択・再読込みしても古い結果が混ざらない。
4. 再起動後のサイズ復元とv0.1.0設定の互換性を確認する。
5. PNG/JPEG、日本語・空白・記号を含むパスをフォトに渡せる。別の既定画像アプリでもフォトが開く。
6. フォトなし・起動エラー・ファイル削除を扱い、ダブルクリック1回で重複起動しない。
