# KuniVRCPhotEditor v0.4.1 開発版

v0.4.1ではシンプル表示に「同室者」「モデル候補」を追加し、名前と取得状態を表示します。モデル候補は手動確定した「モデル」と分け、未観測と候補なしを区別します。OCRで候補を自動生成する機能は未実装です。

「人物記録設定 ▼」→「参加者自動記録の設定…」からログ・写真フォルダーと必要に応じて対象PIDを設定し、「設定を保存」します。ログ初期値は `%AppData%\..\LocalLow\VRChat\VRChat`、写真初期値はWindowsのPicturesフォルダー配下のVRChatです。最新ログは名前の日時で自動選択し、記録中も切り替えます。設定済みのフォルダーは保持します。

サイドビュー選択の右の「記録開始」で監視と自動記録をまとめてONにします。OFFは青ボタン＋灰色丸、ONは赤ボタン＋点滅丸です。ONでもVRChat／ログ待ちや保留があるため、状態欄も確認してください。「記録停止」で停止します。起動直後はOFFで、監視開始前の既存写真を一括変更しません。

記録中に新しく検出したPNG/JPEGは撮影ログと照合し、撮影時点の同室者をXMPへ上書き記録します。上書き前に同じフォルダーへAB_バックアップを必ず作成し、既存の作成数上限を使用します。バックアップ失敗時は上書きしません。参加者情報は写真を共有した際にメタデータとして渡るためご留意ください。Stage3のWebP自動記録は未対応です。詳細は [STAGE3_IMPLEMENTATION.md](STAGE3_IMPLEMENTATION.md) を参照してください。


v0.3.8では複数編集開始のメタデータ確認を最大2ワーカーへ分散し、読込み件数とアニメーションを画面下部に表示します。単体／一括保存は開始直後から処理中表示を行い、一括では保存前確認・コピー準備・保存済み件数・バックアップ整理の段階を表示します。詳細は [V0.3.8_PLAN.md](V0.3.8_PLAN.md) を参照してください。

v0.3.7では画像の余白・透明部分をテーマ色へ統一し、一括編集コピーの準備を最大2スレッドへ分散しました。サムネイルはCPUに応じて最大4スレッドで生成します。一括保存結果は件数表示とし、サイドビュー「なし」で一覧を広く表示できます。

PNG/JPEG/WebPのメタデータ編集・上書き／別名保存、自動バックアップ、チェック式バックアップ削除、検索、ライト／ダーク切替に対応しています。
2026-10-10にv0.4.1 Debug／Releaseの全自己・UI試験と各20回の終了試験が成功しました。新配置・項目・色は試験画面で確認済みです。実写真への自動記録と実VRChatのログ切替は未検証です。

VS2022ではDocumentsの親フォルダーにある `KuniVRCPhotEditor.sln` を開き、Debug / x64を選び、Ctrl+Shift+Bでビルド、Ctrl+F5で起動します。

詳細タブの「編集」から撮影日時・撮影者・ワールド名・ワールドID・被写体名一覧を変更できます。被写体名は1行1名で入力します。入力変更は「値を設定」として扱い、保持したい項目は「変更しない」、削除は「値を削除する」を選びます。「保存」で「上書き保存」または「別名コピーとして保存」を選びます。別名保存では既存の保存先を置換しません。WebPも静止画像・アニメーションのXMPを再圧縮せず編集できます。タグは1行1タグで入力し、「値を設定」で置換、「追加」で既存タグへ追加、「値を削除する」で全削除します。空行・前後の空白・重複は除き、タグ中の空白や#は保持します。保存失敗・保存先選択キャンセルでは編集を保持します。詳しいタグ・保持方針・保存できない条件は [STAGE2_IMPLEMENTATION.md](STAGE2_IMPLEMENTATION.md) を参照してください。

Ctrl／Shiftクリックで複数選択し「編集」を押すと、撮影者・ワールド名・ワールドID・モデル・タグを一括編集できます。撮影日時は変更できません。異なる値は「複数の値」と表示し、初期はすべて「変更しない」です。選んだ変更だけを適用します。一括コピーでは保存フォルダーを選び、元名に `_edited` を付けて保存します。保存前に対象と変更項目を確認し、進捗と対象／成功／失敗／未処理の件数を表示します。ファイル名は保存前の確認で表示し、結果では列挙しません。編集コピーの生成・検証は最大2スレッド、バックアップと原本置換は対象順に確定します。中止は画像間で反映し、失敗時も成功済みは保存されたままです。編集画面からの再試行は失敗・未処理のみが対象です。項目の仕様は [V0.3.5_PLAN.md](V0.3.5_PLAN.md)、並列保存と表示の仕様は [V0.3.7_PLAN.md](V0.3.7_PLAN.md) を参照してください。

自動バックアップは初期ON、上限は初期10件です。上書き前の画像を同じフォルダーへ `AB_<元名>__<UTC日時>_<識別子>.<拡張子>` としてコピーし、内容を検証してから保存します。バックアップまたは管理記録の保存に失敗した場合は原本を変更しません。バックアップOFFでは上書き前のコピーを残しません。別名保存にはバックアップを作りません。

上限はフォルダー単位のアプリ管理バックアップ合計で、1～1000件に変更できます。超過分は上書き成功後に古い順にごみ箱へ移動します。EXE配下の `backups.json` と内容が一致するものだけが自動整理対象です。外部変更されたバックアップや一般のAB_画像は自動整理しません。ごみ箱へ移動できない場合は失敗を通知し、完全削除へ切り替えません。

オプションの「バックアップ削除」では、ロード済みフォルダー直下の `AB_` から始まるPNG/JPEG/WebPを表示します。チェックされたファイルだけを確認後にごみ箱へ移動します。管理対象は初期チェックON、管理対象外はOFFです。「すべて選択／解除」も使えます。選択表示中のバックアップも削除できます。未保存編集がある場合は保存／破棄／キャンセルを確認し、対象が選択中なら表示を解除してから削除します。一覧取得後に変更された画像、サブフォルダー・リンクは除外します。削除できなかった対象名と説明を表示します。

検索はテキスト入力後に「検索」を押すか、検索欄でEnterを入力すると適用されます。IME変換中のEnterとキーの自動反復は除外し、検索中のEnterでは中止・多重実行しません。大文字小文字を区別しない部分一致で、空欄を検索すると全件表示へ戻ります。サブフォルダーは検索しません。初期状態はファイル名検索です。オプションの「メタデータ検索モード」をONにすると時間がかかる旨を確認し、XMP・WICで取得できたテキストメタデータも検索します。検索中は同じボタンの「中止」で取り消せます。未保存の編集がある場合は保存／破棄／キャンセルで保護します。

オプションの「ナイトモード」でライト／ダークを切り替えます。初期はライト。画像の余白・透明部分はテーマ色へ合成し、不透明な画素と画像ファイルは変更せず、OS側のファイル選択・確認ダイアログはOSテーマで表示されます。ヘルプ▼の「バージョン」から版番号とGitHubのDocumentsへのリンクを確認できます。

プレビューは一覧のサムネイルを拡大して表示し、XMP解析完了を待ちません。プレビューのダブルクリックでもWindowsフォトを起動できます。未保存の編集内容はWindowsフォトへ反映されません。

パス入力後はEnterまたは「ロード」。現在と同じフォルダーならキャッシュをクリアして再読込みし、存在する選択画像を保持します。別のアドレスならそのフォルダーへ切り替えます。空欄・無効パスでは現在の一覧を保持します。フォルダー選択ボタン、履歴、ブックマークからもロードできます。
画像を選択するとプレビューとWICで取得できたメタデータを表示します。
プレビュー上のホイールで前後の画像に切り替えます。配置は右・左・下・なしを選べます。「なし」ではプレビューとメタデータ欄を隠し、一覧を広げます。未保存編集がある場合は保存／破棄／キャンセルを確認してから隠します。設定は再起動後も復元します。
ロードで一覧を更新します。画像の変更は編集後の保存操作で行います。
PNG / JPEG / WebPを一覧・プレビューで表示します。WebPはデコーダーをEXEに組み込んでいるため、WebP拡張の追加インストールは不要です。透過・可逆・非可逆圧縮に対応し、アニメーションは合成済みの先頭フレームを静止表示します。
サムネイルはCPUの論理プロセッサ数に応じて1〜4ワーカー（不明時2）で並列生成します。表示範囲と周辺のサムネイルを優先生成し、選択画像の読込みは別ワーカーで処理します。256px相当の生成済み画像を再利用し、Ctrlホイールでは表示サイズだけを変更します。キャッシュがなければ生成します。
オプション▼から「画像サムネイルキャッシュ上限」を変更できます。初期100MB（1MB=1,000,000バイト）、16〜2048MBの整数。LRU内の画像データとImageListの画像・マスクの実ビットマップ保持量を合計して予算を割り当てます。画像一覧のスロット数もサイズ・予算に応じて変わり、最大512＋プレースホルダーです。
これは保持画像データの上限で、デコード中の作業領域、プレビュー、待機結果、管理領域やアプリ全体のメモリ上限ではありません。ディスクキャッシュは作りません。低い上限で画面内の全件を保持できない場合は、一部をプレースホルダーとして残し、状態欄に表示します。
ファイルサイズ・更新日時でキャッシュを失効し、同じフォルダーの「ロード」では明示的にキャッシュをクリアします。
ウィンドウを拡縮すると一覧領域とサムネイルの列数が変わります。
一覧の画像間隔は横8px、縦はファイル名1行分＋8pxを基準に詰めています。既定幅128pxでは、この環境の配置間隔は136×116pxです。ファイル名は1行の省略表示とし、マウスを重ねると拡張子・読込みエラー表示を含む全文をツールチップに表示します。画像全体と縦横比を保つため、4:3枠内の比率由来の余白は残ります。
一覧上のCtrl＋マウスホイールで、上方向はサムネイルを拡大、下方向は縮小します。幅64〜256px、32px刻み、既定128pxです。サイズは再起動後も復元します。
サムネイルをダブルクリックするとWindowsフォトを明示指定して画像を渡します。フォトが見つからない・起動できない場合はエラーを通知します。既定アプリ・関連付けは変更しません。

メタデータ欄は「シンプル」「詳細」タブで切り替えます。シンプルが初期表示で、画像を切り替えても選択中のタブを保持します。
シンプルにはファイル名、容量（1MB=1,000,000バイト、小数2桁）、解像度、作成日時、撮影者、ワールド名、ワールドID、モデル、タグを表示します。値は選択・コピーでき、長文は折り返してスクロールできます。
作成日時はxmp:CreateDate、指定形式のVRChatファイル名、ファイル作成日時、更新日時の順で取得し、取得元を添えます。ファイル名由来は「推測」と表示します。
対応するファイル名の例は `VRChat-2026-10-09-21-30-45.123456_1920x1080.png` です。接頭辞・区切り・日付を厳密に確認し、別形式は推測対象にしません。
撮影者はxmp:Author、ワールド名はvrc:WorldDisplayName、ワールドIDはvrc:WorldIDを使い、欠落時は空欄です。モデルにはアプリ独自XMPタグの被写体名一覧を表示し、欠落時は空欄です。

設定はEXEと同じフォルダーのsettings.jsonに保存されます。Debug版とRelease版は別々の設定になります。
オプション▼の「フォルダ履歴保存」は初期ON。OFFにすると保存済み履歴を空にし、最後のフォルダーも保存・自動復元しません。起動中は現在のフォルダーから新しく履歴を保持します。ONに戻すとその起動中の履歴の保存を再開し、消した過去の履歴は復元しません。
ブックマーク▼の「このアドレスを追加」で入力欄のフォルダーを登録できます。追加だけではロードしません。登録先の選択でロードし、「ブックマークを削除」サブメニューで削除できます。重複を防ぎ、開けなくなった登録先も自動削除しません。ブックマークは履歴保存OFFでも保存されます（上限1000件）。
設定形式はversion=3で、旧version=1/2も読込み可能です。新項目がない旧設定では自動バックアップON・上限10・ライト・メタデータ検索OFFを使用します。
壊れた設定を検出した場合は元ファイルを保全し、その起動中は保存を止めます。修復するにはアプリを閉じて元ファイルをバックアップ・移動し、再起動してください。

タグは標準XMP `dc:subject` の `rdf:Bag` に保存し、モデルの独自タグとは分けます。タグ検索にはメタデータ検索モードをONにしてください。WebP保存では画像・透過・アニメーション・ICC・EXIF・未知チャンクを保持し、XMPと必要なRIFF／VP8X管理情報だけを書き換えます。

## 現在の制限

- 第1段階の完成版ではありません。XMP直接抽出はPNGの非圧縮iTXt / tEXt、JPEGの標準APP1とExtended XMP、WebPのRIFF XMPチャンクが対象です。Extended XMPは標準側の参照GUIDと分割チャンク・MD5を検証して復元します。拡張の破損時も標準XMPを保持し、項目の矛盾は標準側を優先して詳細に記録します。XMP合計上限16MiB、拡張チャンク収集上限1024件。PNGの圧縮XMPは引き続き未対応です。
- 汎用RDF全構造の統合は未対応です。編集対象は上記6項目に限定し、不正なXMP・WebP構造では保存を拒否します。EXIF全種類の対応、実際のVRChat写真のXMP、新UIの目視確認は未実施です。
- フォト起動は、このPCの通常ユーザー環境でAPIの成功を確認し、2026-10-09にユーザーから目視確認も問題なしとの報告を受けました。別の既定画像アプリを設定した環境、別PCのフォトのバージョンは引き続き検証対象です。
- 650枚以上の合成画像で優先生成・スクロール・保持上限・選択保持を自動確認しています。実機の目視確認と実写真フォルダーでの改善倍率は未確認です。
- WebPの入力は256MiB、静止画像は64Mi画素、アニメーションは16Mi画素まで。WIC画像も64Mi画素までとし、上限超過は読込みエラーにします。WebPのEXIF回転・ICC色管理は未対応で、チャンクが存在すれば詳細に表示します。
- WebPのWindowsフォト表示は対象PCのフォト側にも依存し、この改修では実機確認していません。
- EXIFのOrientationに応じた回転表示、DPI調整はまだありません。
- 壊れた画像の詳細はその画像を選択して確認してください。

## ビルドと自動確認

`build.cmd` はこのPCのVS2022 Communityインストール先を使用します。`build.cmd Release` でRelease / x64をビルドします。
生成先は `x64\Debug\KuniVRCPhotEditor.exe` または `x64\Release\KuniVRCPhotEditor.exe` です。
ReleaseはCRTを静的リンクする設定ですが、配布先での検証はまだ実施していません。
libwebp 1.6.0の公式ソースをthird_partyに同梱し、WebP.propsでデコーダーとdemuxのみをビルドします。追加のCMake・パッケージ管理ツールは不要です。配布時にはEXEと同じフォルダーに生成されるTHIRD_PARTY_NOTICES.md、libwebp-COPYING.txt、libwebp-PATENTS.txtを含めてください。

EXEを `--self-test` 引数で実行すると、EXE配下のself-test-dataに試験用PNG/JPEG、破損PNG、設定JSON、result.txtを作成します。
アプリ画面は表示せず、縮小デコード・縦横比・基本情報・メタデータ列挙・設定JSONの往復・パス正規化・破損画像の拒否を確認します。
実際のsettings.jsonは試験で上書きしません。GUI操作や全要件の完了を保証する試験ではありません。

v0.1.1では、自動確認にサイズ上下限、細かいホイール入力、旧設定との互換性、サイズ保存、フォト未検出・ファイル削除時の失敗処理も追加しています。
`--ui-test` は `--self-test` の後に実行します。試験用のWin32ウィンドウで一覧リサイズ・列数変更、Ctrlホイール、選択保持、再読込み、旧サイズ結果の破棄、空白のダブルクリックを確認し、ui-result.txtを出力します。
`verify.cmd`（Debug）または `verify.cmd Release` で両方の試験を実行できます。`build.cmd Release Test` はビルド後にこれらを実行します。
`verify.cmd Release Photos` または `build.cmd Release Test Photos` はさらにフォト起動試験を実行します。この試験では試験画像をWindowsフォトに渡し、photos-result.txtを出力します。APIが成功しても画像表示の目視確認は別途必要です。

v0.1.2の自動確認には日時優先順位・ファイル名推測・XMPの属性/要素/配列・名前空間・不正XML・PNG CRC・欠落時の表示、両タブと各配置の位置揃え・長文折返し・スクロールも含みます。試験用の合成画像を使用しており、VRChat実写真の互換性確認とは区別します。

次版の試験には旧設定移行・履歴OFF・ブックマーク保存、ロード統合、可変キャッシュ予算、64KB超のExtended XMPと破損拒否も含みます。--ui-testでは数値入力・チェック一覧ダイアログと、描画確認時の主ウィンドウを短時間表示して自動操作します。本番settings.jsonには書き込みません。

v0.3.1の自己試験には上書き前の完全コピー、バックアップON/OFF、外部変更・読取り専用・管理記録保存失敗、上限整理と削除失敗時の新しい世代保持を含みます。試験用AB画像だけをごみ箱へ移します。UI試験ではチェック解除・0件時の削除無効化、チェック対象だけの非同期削除、検索・中止・未保存保護・保存後の検索維持、両テーマ・3配置を確認し、self-test-dataへ描画確認PNGを出力します。verify.cmdは最後に `--shutdown-test` による即時起動・終了を20回確認します。

複数選択の表示更新は操作の最後にまとめます。v0.3.7では大量選択・解除時の再配置をなくし、画面外をまたぐShift範囲選択を検証しています。
