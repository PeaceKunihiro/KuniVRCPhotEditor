# KuniVRCPhotEditor v0.3.0 開発版

v0.2.1までの機能に、PNG/JPEGのメタデータ編集・別名コピー保存、サムネイルによる即時プレビュー、プレビューからのWindowsフォト起動を追加しています。
2026-10-10にDebug / Releaseのビルドと自動確認が成功しています。実写真と新UIの目視確認は未実施です。

VS2022ではDocumentsの親フォルダーにある `KuniVRCPhotEditor.sln` を開き、Debug / x64を選び、Ctrl+Shift+Bでビルド、Ctrl+F5で起動します。

詳細タブの「編集」から撮影日時・撮影者・ワールド名・ワールドID・被写体名一覧を変更できます。被写体名は1行1名で入力します。入力変更は「値を設定」として扱い、保持したい項目は「変更しない」、削除は「値を削除する」を選びます。「保存」で別名コピーを指定してください。原本・既存ファイルの上書きはできません。WebPは閲覧のみです。保存失敗・保存先選択キャンセルでは編集を保持します。詳しいタグ・保持方針・保存できない条件は [STAGE2_IMPLEMENTATION.md](STAGE2_IMPLEMENTATION.md) を参照してください。

プレビューは一覧のサムネイルを拡大して表示し、XMP解析完了を待ちません。プレビューのダブルクリックでもWindowsフォトを起動できます。未保存の編集内容はWindowsフォトへ反映されません。

パス入力後はEnterまたは「ロード」。現在と同じフォルダーならキャッシュをクリアして再読込みし、存在する選択画像を保持します。別のアドレスならそのフォルダーへ切り替えます。空欄・無効パスでは現在の一覧を保持します。フォルダー選択ボタン、履歴、ブックマークからもロードできます。
画像を選択するとプレビューとWICで取得できたメタデータを表示します。
プレビュー上のホイールで前後の画像に切り替えます。配置は右・左・下を選べます。
ロードで一覧を更新します。画像ファイルへの書込みは行いません。
PNG / JPEG / WebPを一覧・プレビューで表示します。WebPはデコーダーをEXEに組み込んでいるため、WebP拡張の追加インストールは不要です。透過・可逆・非可逆圧縮に対応し、アニメーションは合成済みの先頭フレームを静止表示します。
表示範囲と周辺のサムネイルを優先生成し、選択画像の読込みは別ワーカーで処理します。256px相当の生成済み画像を再利用し、Ctrlホイールでは表示サイズだけを変更します。キャッシュがなければ生成します。
オプション▼から「画像サムネイルキャッシュ上限」を変更できます。初期100MB（1MB=1,000,000バイト）、16〜2048MBの整数。LRU内の画像データとImageListの画像・マスクの実ビットマップ保持量を合計して予算を割り当てます。画像一覧のスロット数もサイズ・予算に応じて変わり、最大512＋プレースホルダーです。
これは保持画像データの上限で、デコード中の作業領域、プレビュー、待機結果、管理領域やアプリ全体のメモリ上限ではありません。ディスクキャッシュは作りません。低い上限で画面内の全件を保持できない場合は、一部をプレースホルダーとして残し、状態欄に表示します。
ファイルサイズ・更新日時でキャッシュを失効し、同じフォルダーの「ロード」では明示的にキャッシュをクリアします。
ウィンドウを拡縮すると一覧領域とサムネイルの列数が変わります。
一覧の画像間隔は横8px、縦はファイル名1行分＋8pxを基準に詰めています。既定幅128pxでは、この環境の配置間隔は136×116pxです。ファイル名は1行の省略表示とし、マウスを重ねると拡張子・読込みエラー表示を含む全文をツールチップに表示します。画像全体と縦横比を保つため、4:3枠内の比率由来の余白は残ります。
一覧上のCtrl＋マウスホイールで、上方向はサムネイルを拡大、下方向は縮小します。幅64〜256px、32px刻み、既定128pxです。サイズは再起動後も復元します。
サムネイルをダブルクリックするとWindowsフォトを明示指定して画像を渡します。フォトが見つからない・起動できない場合はエラーを通知します。既定アプリ・関連付けは変更しません。

メタデータ欄は「シンプル」「詳細」タブで切り替えます。シンプルが初期表示で、画像を切り替えても選択中のタブを保持します。
シンプルにはファイル名、容量（1MB=1,000,000バイト、小数2桁）、解像度、作成日時、撮影者、ワールド名、ワールドID、モデルを表示します。値は選択・コピーでき、長文は折り返してスクロールできます。
作成日時はxmp:CreateDate、指定形式のVRChatファイル名、ファイル作成日時、更新日時の順で取得し、取得元を添えます。ファイル名由来は「推測」と表示します。
対応するファイル名の例は `VRChat-2026-10-09-21-30-45.123456_1920x1080.png` です。接頭辞・区切り・日付を厳密に確認し、別形式は推測対象にしません。
撮影者はxmp:Author、ワールド名はvrc:WorldDisplayName、ワールドIDはvrc:WorldIDを使い、欠落時は空欄です。モデルは被写体名表示用の予約で、現在は空欄です。

設定はEXEと同じフォルダーのsettings.jsonに保存されます。Debug版とRelease版は別々の設定になります。
オプション▼の「フォルダ履歴保存」は初期ON。OFFにすると保存済み履歴を空にし、最後のフォルダーも保存・自動復元しません。起動中は現在のフォルダーから新しく履歴を保持します。ONに戻すとその起動中の履歴の保存を再開し、消した過去の履歴は復元しません。
ブックマーク▼の「このアドレスを追加」で入力欄のフォルダーを登録できます。追加だけではロードしません。登録先の選択でロードし、「ブックマークを削除」サブメニューで削除できます。重複を防ぎ、開けなくなった登録先も自動削除しません。ブックマークは履歴保存OFFでも保存されます（上限1000件）。
設定形式はversion=2へ更新し、旧version=1も読込み可能です。追加項目がない旧設定は100MB・履歴ON・空のブックマークとして扱います。
壊れた設定を検出した場合は元ファイルを保全し、その起動中は保存を止めます。修復するにはアプリを閉じて元ファイルをバックアップ・移動し、再起動してください。

## 現在の制限

- 第1段階の完成版ではありません。XMP直接抽出はPNGの非圧縮iTXt / tEXt、JPEGの標準APP1とExtended XMP、WebPのRIFF XMPチャンクが対象です。Extended XMPは標準側の参照GUIDと分割チャンク・MD5を検証して復元します。拡張の破損時も標準XMPを保持し、項目の矛盾は標準側を優先して詳細に記録します。XMP合計上限16MiB、拡張チャンク収集上限1024件。PNGの圧縮XMPは引き続き未対応です。
- 汎用RDF全構造の統合やメタデータ編集は実装していません。シンプルの既存項目と生XMPの表示が対象です。EXIF全種類の対応、実際のVRChat写真のXMP、新UIの目視確認は未実施です。
- フォト起動は、このPCの通常ユーザー環境でAPIの成功を確認し、2026-10-09にユーザーから目視確認も問題なしとの報告を受けました。別の既定画像アプリを設定した環境、別PCのフォトのバージョンは引き続き検証対象です。
- 650枚以上の合成画像で優先生成・スクロール・保持上限・選択保持を自動確認しています。実機の目視確認と実写真フォルダーでの改善倍率は未確認です。
- WebPの入力は256MiB、静止画像は64Mi画素、アニメーションは16Mi画素まで。WIC画像も64Mi画素までとし、上限超過は読込みエラーにします。WebPのEXIF回転・ICC色管理は未対応で、チャンクが存在すれば詳細に表示します。
- WebPのWindowsフォト表示は対象PCのフォト側にも依存し、この改修では実機確認していません。
- EXIFのOrientationに応じた回転表示、DPI調整はまだありません。
- 壊れた画像の詳細はその画像を選択して確認してください。

## ビルドと自動確認

`build.cmd` はこのPCのVS2022 Communityインストール先を使用します。`build.cmd Release` でRelease / x64をビルドします。
生成先は `x64\Debug\KuniVRCPhotEditor.exe` または `x64\Release\KuniVRCPhotEditor.exe` です。
ReleaseはCRTを静的リンクする設定ですが、配布先での検証はまだ実施していません。
libwebp 1.6.0の公式ソースをthird_partyに同梱し、WebP.propsでデコーダーとdemuxのみをビルドします。追加のCMake・パッケージ管理ツールは不要です。配布時にはEXEと同じフォルダーに生成されるTHIRD_PARTY_NOTICES.md、libwebp-COPYING.txt、libwebp-PATENTS.txtを含めてください。

EXEを `--self-test` 引数で実行すると、EXE配下のself-test-dataに試験用PNG/JPEG、破損PNG、設定JSON、result.txtを作成します。
アプリ画面は表示せず、縮小デコード・縦横比・基本情報・メタデータ列挙・設定JSONの往復・パス正規化・破損画像の拒否を確認します。
実際のsettings.jsonは試験で上書きしません。GUI操作や全要件の完了を保証する試験ではありません。

v0.1.1では、自動確認にサイズ上下限、細かいホイール入力、旧設定との互換性、サイズ保存、フォト未検出・ファイル削除時の失敗処理も追加しています。
`--ui-test` は `--self-test` の後に実行します。非表示のWin32ウィンドウで一覧リサイズ・列数変更、Ctrlホイール、選択保持、再読込み、旧サイズ結果の破棄、空白のダブルクリックを確認し、ui-result.txtを出力します。
`verify.cmd`（Debug）または `verify.cmd Release` で両方の試験を実行できます。`build.cmd Release Test` はビルド後にこれらを実行します。
`verify.cmd Release Photos` または `build.cmd Release Test Photos` はさらにフォト起動試験を実行します。この試験では試験画像をWindowsフォトに渡し、photos-result.txtを出力します。APIが成功しても画像表示の目視確認は別途必要です。

v0.1.2の自動確認には日時優先順位・ファイル名推測・XMPの属性/要素/配列・名前空間・不正XML・PNG CRC・欠落時の表示、両タブと各配置の位置揃え・長文折返し・スクロールも含みます。試験用の合成画像を使用しており、VRChat実写真の互換性確認とは区別します。

次版の試験には旧設定移行・履歴OFF・ブックマーク保存、ロード統合、可変キャッシュ予算、64KB超のExtended XMPと破損拒否も含みます。--ui-testでは主ウィンドウは非表示ですが、数値入力ダイアログは短時間表示して自動操作します。本番settings.jsonには書き込みません。
