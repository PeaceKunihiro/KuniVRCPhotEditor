# KuniVRCPhotEditor Stage4：今後の機能・検証計画

作成日：2026-10-11。基準版：v0.4.12。

## 目的・位置付け

v0.4.12までの閲覧・編集・人物記録を基盤に、残っている機能と実環境での品質確認を整理する。本書は今後の作業の一覧であり、実装開始や全項目の採用を確定する指示ではない。バージョン番号・実装順序の確定は、個別改修の指示時に行う。過去の版別検討書の「未実装」は、その版当時の状態として扱う。

OCR精度の追加改善はv0.4.11で終了した。既存OCRは補助機能として維持し、不具合修正を精度改善とは分けて扱う。

## S4-01：候補の手動確認

- 記録済みModelCandidatesを一覧で表示し、選んだ名前をModels（手動確定モデル）へ反映できるようにする。
- 候補の除外は、既存の自動観測記録を無断で削除する操作とは分ける。除外状態の保存先・タグ・再処理時の保持方法は実装前に確定する。
- InstanceMembersは同室者、ModelCandidatesは推測、Modelsは手動確定という区別を維持する。
- 候補がない画像でも既存のモデル手入力を利用できる。人物名を推測して追加しない。
- 既存編集・未保存確認・上書き／コピー保存・AB_バックアップを再利用する。人物名の保存・再読込みと、再処理による手動確定の保持を検証する。
- OCRエンジンや認識閾値の変更は含めない。保存タグの追加が必要なら、既存データとの互換性を確認してから仕様を定める。

## S4-02～05：閲覧対応の拡充

圧縮XMPは読取りから検討し、書込み対応と区別する。展開後サイズなどの制限、破損データ、既存タグの保持を定義する。EXIF回転とICCは表示処理へ適用し、元画像の画素やメタデータを書き換えない。ディスクキャッシュの形式・キー変更が必要な場合は、古いキャッシュを誤利用しない移行を行う。

DPI対応ではフォント、ボタン、一覧、メタデータ、各設定画面、サイドビュー境界の寸法を一貫して扱う。拡縮・配置切替時の再描画不具合を再発させない。各項目の対応形式・対象範囲・完了条件は実装前に個別仕様へ展開する。

## S4-06：保存中断時の復旧支援

現状は通知された復旧用原本を手動で回収する。将来の復旧支援では管理記録・元画像・一時保存・AB_の状態を照合し、復旧可能な操作を説明して選択できる案を検討する。起動時の無条件な上書き、失敗項目の自動再投入、根拠のない一時ファイル削除は行わない。方式を確定し、専用データによる強制中断試験が済むまで自動復旧を実装済みとは扱わない。

## S4-07：音声認識の保留条件

VRChatのオーディオ出力とマイク入力の取得方法は既に調査した。認識器・モデル配布・動作条件・負荷・誤認識への対処は未確定。実装する場合も入力元を明示し、ユーザーの開始操作を必要とする。呼ばれた名前を発話者や写真内被写体と断定しない。Stage4の必須機能には含めない。

## 機能追加とは別の検証・不具合対応

以下は新規機能の実装予定とは区別する。原因を確認して必要な修正を判断する。

| 対象 | 残る確認 |
|---|---|
| 配布・起動 | フレンド環境の起動不可原因、配布EXEのサイズ／ハッシュ、ZIP展開・別PCでの動作 |
| 人物自動記録 | 最新ログ切替、起動／停止／再起動、部分ログ、非公開ワールド・連続入室、ID設定、F12推定時刻 |
| 保存・削除 | 実写真の一括編集、容量不足・アクセス拒否、ネットワーク先のごみ箱不可、中断時の保全 |
| 閲覧・操作 | IMEを含むEnter検索、画面外Shift選択、再描画、長いパス／UNC、移動されたPictures |
| キャッシュ | 実写真での速度・容量、OFF／削除、保存先不可、複数起動時の共有競合 |
| 更新確認 | 通信失敗、低速・キャンセル、保存失敗、他PCでのブラウザー起動 |
| OCR既存機能 | 停止／再開・対象切替・表示・資源解放の不具合確認。精度向上の追加研究は行わない |

開発時の試験書込みはself-test-dataだけで行い、指定された写真・ログ・録画は読取り専用とする。実地確認と合成データの試験を区別する。

## 終了済み・対象外

- OCR精度の追加改善：別エンジン比較／変更、GPU化によるOCR改善、回転補正、照合基準の追加緩和。終了判断は[査読文書](V0.4.11_OCR_REVIEW.md)を参照する。
- 自動更新・EXEの自動差替え、API認証の追加、録画編集などを、本書で新たな予定機能へ追加しない。
- Stage1～Stage3のうち実装済みの機能は、改めて未実装予定へ戻さない。技術全般の限界や、Stage3全要件の達成を宣言する文書ではない。

## 推奨する進め方（順序案）

1. 既存機能と配布の不具合・実環境検証を優先する。
2. Stage3残要件の候補採用／除外UIを個別仕様にする。
3. 圧縮XMP・EXIF回転・ICC・DPIを必要性に応じて個別採用する。
4. 保存復旧は安全性を先に検証し、音声認識は保留を維持する。

進捗と次の作業は[work](../../work_logs/KuniVRCPhotEditor_work.md)、日付ごとの判断・結果は[history](../../work_logs/KuniVRCPhotEditor_history.md)へ記録する。機能一覧の採用・終了が変わった場合は本書を更新する。
