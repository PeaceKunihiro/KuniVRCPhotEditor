# KuniVRCPhotEditor Stage5：MDB・写真カテゴライズ仕様

作成日：2026-10-18（日本時間）。基準版：v0.5.5。

[機能説明](../README.md)／[更新履歴](UPDATELOG.md)／[Stage4](KuniVRCPhotEditor_Stage4.md)

## 1. 目的と位置付け

MDB（Metadata DataBase）は、写真から抽出したメタデータをローカルに保持する検索用DB兼永続キャッシュである。画像ファイルを繰り返し開いて解析する負担を減らし、メタデータ検索・頻出項目の集計・カテゴリ別表示に利用する。

本書は将来実装の仕様であり、実装開始・提供バージョン・Stage4の実施順序を確定するものではない。ユーザー指定の機能と、それを成立させるための補完仕様案を整理する。未確定事項は末尾にまとめ、実装時に黙って確定しない。

- 写真内のメタデータを正本とし、MDBは削除されても再構築できる派生データとする。
- 初期OFF。サムネイルのメモリー／ディスクキャッシュとは別の設定・保存領域・容量管理を持つ。
- MDBの作成・集計・分類で原画像や写真内メタデータを書き換えない。物理的なフォルダー分けや画像コピーは行わない。
- MDB機能が画像・メタデータを外部サーバーへ送信することはない。名称取得のための外部API照会も本仕様に含めない。既存の更新確認など、MDB以外の通信設定とは区別する。

## 3. ［オプション］→［MDB設定］

独立ダイアログを追加する。初期設定はMDB OFF、容量方式は固定値、固定値100MBとする。

| 要素 | 内容 |
|---|---|
| ［MDB：ON/OFF］ | 初期OFF。ONで収集・参照・集計・カテゴリ表示を利用可能にする |
| 機能説明 | 下記の説明を常時表示する |
| ［MDB容量］ | ［設定値］［自動値］［無制限］の3方式を選択する |
| 設定値入力 | 初期100MB。固定値方式で有効とし、他方式に切り替えても入力値を保持する |
| 使用状況（補完案） | 使用量／有効上限、登録画像件数、収集中・未収集・エラーの状態を表示する |
| ［適用］［キャンセル］（補完案） | 適用で変更し、キャンセルでは変更しない。設定は再起動後も保持する |

説明文の例：

> MDB（Metadata DataBase）は、写真のメタデータをこのPC内に収集・保持し、メタデータ検索やカテゴリ別表示に利用する機能です。画像を読み込んだ際に順次記録し、専用のキャッシュを作成します。MDB機能によって画像やメタデータが外部サーバーへ送信されることはありません。元の写真データ全体を保存する機能ではありません。

OFF時は新規収集・MDBを用いた検索・カテゴライズを停止する。従来のメタデータ直接検索は維持する。既存MDBをOFF切替だけで削除しない方式を補完案とし、その旨を説明する。再度ONにした際は変更確認後に再利用する。

保存先は既存のポータブル運用に合わせ、EXEと同じ場所の専用フォルダー（例：`MetadataDB`）とする補完案。写真フォルダーやサムネイルキャッシュ内には作成しない。DBファイル名・エンジンは実装方式の選定時に確定する。

### 3.1 容量方式

| 方式 | 扱い |
|---|---|
| 設定値 | 初期100MB。表示単位と実バイト数を一致させる。100MBは100,000,000バイトとする案 |
| 自動値 | ディスクサムネイルキャッシュで保持されている画像のメタデータを優先して登録・保持する。画像の再読み込み時に対応対象を確認する。サムネイルキャッシュと同じバイト数をMDB上限にする意味ではない。数値上限の決め方は第11節の確認事項 |
| 無制限 | MDB独自の容量上限を設けない。保存媒体の空き容量まで無制限に書き込むことは保証しない |

容量にはDB本体・索引・集計情報・ジャーナル等の通常運用で必要な関連ファイルを含める。書込みや再構築の一時領域も考慮し、上限超過・空き容量不足時に原画像や本番設定を変更して回避しない。

固定／自動で上限に達した場合は、古く利用した画像のレコードから整理する方式を補完案とする。画像1枚の情報はまとめて扱い、検索対象の文字列を黙って切り捨てない。1枚分すら収まらない場合はMDB登録を省略して直接解析へフォールバックし、理由を表示する。

容量不足で登録と削除を無限に繰り返さない。現在の検索・表示処理に必要な結果は処理中の一時データとして利用し、永続化できた範囲と区別する。頻出件数の集計範囲も容量整理後の状態へ更新する。

### 3.2 自動方式の登録優先順位（2026-10-18補足）

ユーザーの意図は、ディスクサムネイルキャッシュに対応する画像を優先してMDBに登録することである。対応集合の更新・登録開始は画像の再読み込み時でよく、サムネイル保存のたびに即時同期する必要はない。

1. 現在フォルダーの画像を再読み込みする際、有効なディスクサムネイルキャッシュがある原画像を確認する。
2. 一覧・選択画像の表示を優先した上で、対応画像のうちMDB未登録・メタデータ変更済みの画像を先に解析・登録する。有効なMDBレコードがある場合は再解析しない。
3. その他の画像は通常の読込み・検索・カテゴライズに応じて補完する。優先対象だけに登録を限定せず、ディスクサムネイルの有無で検索結果を欠落させない。
4. 自動方式でMDBの容量整理が必要な場合も、直近の再読み込みで優先対象と確認できた有効レコードを先に残す方針とする。

サムネイルキャッシュ自体には必要なメタデータ全体が保存されていないため、初回登録や変更時は原画像を開いて解析する。サムネイルからメタデータを復元したり、写真を開かずに初回MDBを作れる前提を置いたりしない。

サムネイルが古い・破損している・原画像と対応しない場合は、優先対象として扱わない。対応確認のためだけにサムネイルの利用順位を更新しない。保存済み対応情報を利用できなければ通常のMDB収集へ戻し、ディスクサムネイルキャッシュを勝手にONにしない。

対象は再読み込みした現在フォルダー直下とする。他フォルダーのMDBやキャッシュをその都度全走査しない。サムネイルの削除・容量整理に連動してMDBを即時削除することも必須とせず、次の再読み込み時に優先状態を更新する。フォルダー変更・中止時には古い対象集合を新しい表示へ混ぜない。

## 4. 収集対象と更新

- 対応画像は現行のPNG／JPEG／WebP。画像のサムネイル・プレビュー・メタデータを読み込む際に、未登録または変更された画像を順次解析・登録する。
- フォルダーを開いただけで全登録先や全サブフォルダーを無条件に巡回しない。表示用処理を優先し、検索／カテゴライズで必要となる現在フォルダー直下の未収集分をバックグラウンドで補完する。
- MDBがONであれば、メタデータ検索モードがOFFでも読込みに伴う収集は行う。検索モードは検索対象の切替、MDB設定は収集・再利用の切替として分離する。
- ファイルの場所・サイズ・更新日時などの変更検知情報と解析方式の版を保持する。キャッシュが有効な場合はメタデータを再解析せず再利用する。
- 本アプリでの編集・自動記録は保存成功後にMDBを更新または無効化する。保存失敗時に、保存予定の値を登録しない。
- 外部編集・XnConvert変換・追加・削除・移動を、ロード／再読み込み／利用前の照合で反映する。常時の全ドライブ監視は必須としない。
- 移動先と移動元を確実に対応付けられない場合は新規登録と旧項目の失効で扱う。単に内容が似ている画像やコピーを同一写真へ統合しない。
- ロック中・書込み途中・未接続媒体・アクセス拒否を区別し、未接続だけを理由に全レコードを削除しない。古いレコードを現在有効な検索結果として断定表示しない。
- MDBの破損・書込み不可・中断時は原画像の閲覧・直接検索を継続できるようにする。再構築の手順と状態を表示し、復旧のために原画像へ書き込まない。

## 5. 保持する論理情報

| 情報 | 用途 |
|---|---|
| MDB内の画像識別子・パス・変更検知情報 | 重複表示から実ファイルへの対応、差分更新 |
| ファイル名と既存検索対象のメタデータ文字列 | 現行の部分一致検索を維持。未知のXMPやWIC側情報も検索対象から落とさない |
| タグの配列 | タグ別分類・頻出集計 |
| ワールドID・保存済みワールド名 | ワールド別分類・見出し表示 |
| グループID・取得済みグループ名 | グループ別分類・見出し表示。現行のグループIDタグも抽出対象 |
| 人物名・保存済み人物ID・役割 | 人物別分類・集計。同室者／モデル／モデル候補の由来を保持 |
| 解析状態・更新世代・最終利用 | 未収集・欠損・失敗の区別、古い結果の排除、容量整理 |

人物IDは写真に保存されているものを利用し、名前から推測して補完しない。既存の［ユーザーIDも保存する］初期OFFを変更せず、MDBのONを理由にログやAPIから新たなIDを集めない。

分類時に同室者／モデル／モデル候補をまとめても、元情報の意味や役割をMDB内で失わない。同室者を被写体として確定したり、モデル候補を手動確定モデルへ変更したりしない。

## 6. 検索と実行負荷

- MDB ON時も既存の検索操作と大文字小文字を区別しない部分一致の意味を維持する。ファイル名検索とメタデータ検索の切替も維持する。
- MDBに登録済みの有効な画像はDBを照合し、未登録・変更分は画像から補完する。MDBにないことだけを理由に「該当なし」としない。
- 現在フォルダー直下・既存のAB_表示条件という検索範囲を維持する。MDBに他フォルダーの記録があることを理由に検索範囲を広げない。
- 初回収集・解析と差分更新は複数ワーカーに分担できる構成とする。書込みは集約・まとめ処理し、UIスレッドで画像解析やDB書込み待ちを行わない。
- 項目一致の分類・集計には索引を利用する。任意の部分一致検索の方式は別途検討し、意味を変更して速度を稼がない。
- 検索そのものの複数スレッド化は測定後に判断する。DB導入だけで並列化や一定倍率の高速化を保証しない。HDDで同時ファイル読込みを増やしすぎない。
- 収集中／検索中の件数・進捗と中止手段を用意する。移動・条件変更・終了時は古い世代の結果を現在の一覧へ混ぜない。

## 7. 頻出項目の集計

タグ・ワールド・ユーザーについて、該当する写真の件数を記録し、件数降順で参照できるようにする。同数時は名称またはIDで安定した順序にする。

- 集計の基準は「各項目を含む画像の実件数」。同じ画像内の同一タグ・人物の重複や、複数カテゴリへの表示回数では増やさない。
- 頻出ユーザーは人物ID軸と人物名軸を区別できるようにする。同一画像で同室者・モデル・候補に同じ人物がいても、同じ軸の同一項目には1件と数える。
- 撮影者は検索用メタデータとして保持するが、人物分類・頻出ユーザーの対象は指定された同室者／モデル／モデル候補を基本とする補完案。
- ワールドはIDを集計キーとする。IDのないワールド名を同じワールドと断定してID別統計へ混ぜない。
- 未収集・失敗・空欄・「未観測」「部分的な記録」等の状態表示は名前やタグとして集計しない。
- 統計ではAB_名または【AutoBackup】タグで識別できるバックアップを除外する補完案。カテゴライズ一覧のAB_表示は既存設定に従う。
- 集計範囲を明示する。MDB全体の統計は「保持中の有効な画像」の集計であり、未読込み・容量整理済み・接続未確認の画像まで含めたライブラリー全件の統計とは扱わない。現在フォルダーの統計も未収集件数を併記する。
- 画像更新・削除・失効・容量整理時に集計を更新し、再構築から同じ件数を再現できるようにする。

頻出項目の参照画面の配置、上位何件を表示するか、項目選択で絞り込む操作はUI補完事項として実装前に確定する。保存・集計だけの実装を、頻出一覧まで完成した状態とは扱わない。

## 8. ［並べ替え］のカテゴライズ

MDB ON時に以下の項目を追加する。現在フォルダーの検索・表示条件を適用した結果をグループ化し、フォルダー項目は従来どおり先頭に独立して表示する。

| 項目 | 分類キーと表示 |
|---|---|
| ［タグ別］ | タグごとにグループ化。境界に区切り線とタグ名を表示。複数タグの画像には右下へ重複アイコン |
| ［人物ID別］ | 保存済み人物IDごとにグループ化。境界に区切り線と人物ID（取得済み人物名も併記する案）。複数IDの画像は各グループへ重複表示し、右下へ重複アイコン |
| ［人物名別］ | 人物名ごとにグループ化。同室者／モデル／モデル候補を区別しない。区切り線と人物名も表示する補完案 |
| ［ワールド別］ | ワールドIDごとにグループ化。区切り線に保存済みワールド名を表示する |
| ［グループ別］ | グループIDごとにグループ化。区切り線に取得済みグループ名を表示する |

カテゴリ名の順序は昇順、各カテゴリ内は従来のファイル名／作成日ソートを維持する案とする。通常のソートとカテゴライズの選択状態を区別し、MDB OFFでは従来のソートへ戻す。再起動時にMDBがOFFなら、保存されたカテゴリ表示を無理に復元しない。

タグ・人物名は前後の空白や改行を整理した上で比較し、表示文字列を保持する。人物名別では同じ表示名を同じグループにするが、同一人物と断定しない。人物ID別では同名でもIDが異なれば別グループにする。取得できないIDを名前で代用しない。

ワールド名／グループ名がない場合は「名称不明」とIDを見出しへ表示する補完案。名前が変わった場合もIDが同じなら同じカテゴリとし、各画像に記録された名前は保持する。表示名が競合する場合の代表名は、現在表示対象で最も新しく撮影された写真の非空値を使う案とする。日付も不明な場合は安定したファイル名順で選び、最新版の公式名とは表示しない。

現行はグループIDをタグに記録するが、グループ名の常時取得は実装していない。Stage5でもIDだけから名前を自動取得できる前提を置かない。

### 8.1 重複アイコンと同一画像の操作

素材は [Images/TAGs.png](../Images/TAGs.png) を使用し、サムネイル右下へ重ねる。縮小時も画像や選択枠を過度に隠さず、サイドプレビュー・原画像・保存済みサムネイル自体には焼き込まない。

- 指定上、人物ID別は各IDグループへ重複表示する。タグ別・人物名別の複数カテゴリ所属時の扱いは第11節の補完案を参照する。
- 1つのカテゴリ内に同じ画像を複数回出さない。アイコンは表示中の分類軸に複数の有効値があることを示す。
- 重複行は同じ実画像を参照する。同じ画像の各表示を選択状態に連動させ、複数選択・一括編集・保存・削除・フォト起動等は実画像単位で重複排除して実行する。
- 件数は「実画像数」と「カテゴリ内の延べ表示数」を区別する。Shift選択は区切り線を飛ばし、同じ画像に同じ処理を二度適用しない。
- スクロール・サムネイル割当て・サイドプレビュー・未保存確認でも、表示行番号を画像の識別子として扱わない。区切り線は選択・編集・起動の対象にしない。

### 8.2 情報不足の画像

選択した分類軸の情報がない画像は一覧末尾の独立した領域へ表示し、隠したり他のカテゴリへ推測で割り当てたりしない。

- タグなし、人物IDなし、人物名なし、ワールドIDなし、グループIDなしを選択軸に応じて扱う。
- 有効なキーはあるが表示名だけがない場合は、そのIDのカテゴリへ入れる。
- 未収集・読取り失敗・変更確認待ちは、本当にデータがない画像と表示上区別する。暫定的に末尾へ置き、収集後に該当カテゴリへ移す。
- グループ移動・検索条件変更で選択やフォーカスを別画像へ移さず、未保存編集を勝手に破棄しない。大量の更新はまとめて反映し、1件ごとの一覧全再構築で操作を止めない。

## 9. 実装順序案

1. 保存先・設定・容量方式・変更検知・中断と再構築を設計する。DB方式とライセンス・配布方法を確認する。
2. 収集と既存検索の再利用を実装し、直接検索との一致・初回／再検索・差分更新の時間を測定する。
3. 頻出項目の集計と参照画面を実装する。
4. 表示行と実画像の対応を分離し、区切り線・重複表示・欠損末尾表示・各操作の一意性を実装する。
5. 性能測定に基づいてワーカー数・DB索引・部分一致検索の方式を調整する。

各段階を部分完了として記録する。検索用MDBが完成しても、重複カテゴリ表示を含むStage5全体の完了とはしない。

## 10. 受入確認

- 初期OFF／100MB、設定の適用・キャンセル・再起動、3容量方式の切替、無効入力、空き容量不足、原画像・本番設定の保全。
- 自動方式で再読み込み時にディスクサムネイル保持画像を優先し、未保持画像も検索から漏らさないこと。有効なMDBの再解析を省くこと、サムネイルの追加・削除・無効化が次回再読み込みで反映されること。
- 未登録・変更・外部変換・移動・削除・アクセス不可・再接続・破損DB・中断からの再構築と、古い結果の排除。
- 未収集・容量整理済みを含め、直接検索とMDB検索で対象・部分一致結果が一致すること。初回・再検索・差分更新を分けて測定すること。
- 同室者／モデル／候補の重複名、同名別ID、IDなし、空値・状態文言、同一写真の重複タグ、バックアップ除外による集計件数。
- 5分類、区切り線、名称なし・IDなし・未収集の末尾表示、重複アイコン、延べ表示数と実画像数。
- 重複表示された同じ画像の一括保存・削除等が1回だけ行われること。Shift／Ctrl選択、画面外選択、検索併用、各サイド配置、ファイル名省略のタイル表示。
- 収集中・大量分類中・中止・終了でもUI操作を止めないこと。メモリー／MDB／サムネイルキャッシュの容量と設定が混同されないこと。
- MDB処理に外部送信がなく、ユーザーIDを新規収集しないこと。試験は専用コピー・合成データで行う。

性能の合格値は対象写真枚数・媒体・データ量を定めて実装前に設定する。固定の高速化倍率を本書では保証しない。

## 11. 実装前の確認事項・補完案

| 項目 | 補完案・確認する内容 |
|---|---|
| 自動方式の数値上限 | 優先対象はディスクサムネイル保持画像、登録タイミングは再読み込み時と確定。同じバイト上限を共有する旧案は採用しない。対象画像のメタデータ量から上限を算出するか、固定の安全上限を併用するか等、容量制御の詳細は別途確定する |
| 複数タグ・複数人物名 | 人物ID別と同様、所属する全カテゴリへ重複表示する案。タグ別についてユーザー指定は重複アイコンまでであり、重複表示自体は補完案。複数グループIDも同じ扱いにする案 |
| 頻出項目のUI | ［MDB設定］内の［頻出項目を表示］から専用画面を開き、タグ／ワールド／人物を切り替える案。参照範囲・表示件数・クリックによる絞り込みは確定が必要 |
| その他の境界 | 固定容量の最小／最大値、代表名称の選び方、MDBを明示削除・再構築する入口と確認方法を実装前に確定する |

指定済み要件と補完案を混同せず、実装指示時に確認・採用した内容を本書へ反映する。
