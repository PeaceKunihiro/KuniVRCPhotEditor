# v0.3.8 改修案

2026-10-10 改修を実装。実写真80件の時間計測は未実施。以下の「現状」は改修前の調査。

## 複数画像の編集開始

編集開始時の対象確認は、検索等と共用のバックグラウンドワーカーで1画像ずつ実施している。InspectEditableは画像ファイル全体の読込み、形式・XMP解析、全体のMD5指紋計算を行う。80件ではこの処理が直列に積み上がる。保存コピー生成の最大2ワーカー化は、この編集開始処理には適用されていない。

対象確認を最大2ワーカーへ変更し、結果は選択順で保持する。全件確認後に混在値を編集欄へ反映する。終了・選択変更時は旧結果を破棄し、エラーがあれば不完全な対象一覧で編集を開始しない。全ファイルの同時読込みは避ける。保存時の全体指紋再確認、原本変更検出を省略しない。I/Oが律速の環境では並列化だけで改善しない可能性があるため、合成80件で直列と並列を比較し、実フォルダーの改善率とは区別する。

開始直後から「編集用メタデータ読込み中 0 / 80件」と不定進捗のアニメーションを表示し、完了件数を更新する。終了時に編集画面へ移行し、失敗・選択変更・終了時には表示を解除する。サイドビューの配置とタブに左右されず状態が分かる表示領域を使う。

## 上書き保存

現状の一括保存は1画像の保存確定後に件数表示を更新するが、全件事前確認・コピー準備中には進捗が出ない。単体保存も完了までの進捗通知がない。

保存受付直後から不定進捗のアニメーションと処理状態を表示する。一括では「保存前確認」「保存用コピー準備」「上書き保存 完了件数 / 対象件数」「バックアップ整理」の段階を表示する。単体では処理中表示を常時出し、可能な処理境界で状態を更新する。ファイル内の正確な進捗率・残り秒数は表示しない。原本置換の順序、バックアップ検証、復旧通知を維持し、100%相当の完了表示は最終処理終了後にする。

進捗通知は軽量な専用データとし、画像一覧や全メタデータを毎回コピーしない。頻繁な通知でUIを圧迫しないよう更新を集約する。成功・失敗・中止・終了のいずれでもアニメーションを停止する。一括中止は現在の保存確定を安全に終えてから反映し、単体の原本置換を途中で中断しない。

## 検証

- 80件のPNG/JPEG/WebP混在で読込み時間と同時稼働数、選択順・混在値、破損画像・途中選択変更・終了を確認する。
- 単体／一括上書き、バックアップON/OFF、保存前確認と準備中、失敗・中止・整理中の表示を確認する。
- 原本変更検出・画像と既存メタデータ保持・バックアップ一致・未保存保護を回帰試験する。
- Debug／Releaseの自己・UI・終了試験を実施し、実操作と未検証範囲を区別して記録する。

表示は画面下部のステータス欄を使用し、150msごとに回転記号を更新する。読込みの通知は4件ごとと最終件で行う。単体保存は処理全体の活動表示、一括は処理段階と件数を表示する。

最終Debug／Release x64のビルド・自己／UI試験は終了コード0、各20回の終了試験も成功。80件の混在形式確認（4MBの未知チャンクを持つWebPを含む少数の合成入力を反復）ではDebugが直列156ms／並列79ms、Releaseが156ms／78ms。OSキャッシュのある合成条件であり、実写真80ファイルの改善率を保証しない。読込み順序・指紋一致、失敗と途中選択変更、即時表示とアニメーション、単体／一括保存開始と表示解除、既存バックアップ・未保存保護を確認した。
