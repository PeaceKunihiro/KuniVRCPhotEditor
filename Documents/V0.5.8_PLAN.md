# v0.5.8 ID・表示名対応表／Import・Export仕様

2026-10-18（日本時間）。ユーザーの簡素化案を反映した最新版。基準実装はv0.5.7。後続指示によりv0.5.8として実装し、結果は[実装・検証記録](V0.5.8_IMPLEMENTATION.md)に分離する。

[Stage5：MDB仕様](KuniVRCPhotEditor_Stage5.md)／[機能説明](../README.md)／[更新履歴](UPDATELOG.md)。

## 1. 目的と対象

MDBのID別カテゴリへユーザー指定の表示名を付ける。対応表をMDBとは独立して保持し、Import／Exportで移行できるようにする。APIによる名称取得や、表示名からのID逆引きは行わない。

対象は人物ID（usr_）・ワールドID（wrld_）・グループID（grp_）。対応表の編集・利用・Import／ExportはMDB ON時のみ有効とし、MDB OFFでも保存済み対応表は削除しない。

## 2. 編集画面

［オプション］→［MDB設定］に［ID・表示名の編集…］を追加する。MDB OFF時は無効とする。独立ダイアログ内は次の3列の一覧表と4ボタンで構成する。

| 表示名 | ID | ショートカット |
|---|---|---|
| ユーザーが入力・変更する欄 | 読取り専用 | ［↗］ボタン |

- ［保存］［キャンセル］［Import］［Export］を配置する。取得済み名称の列・種別切替・名称の競合比較画面・解除専用ボタンは設けない。
- 一覧の対象は、MDBに登録された有効なIDと保存済み対応表のIDの和集合。現在のMDBにない手動登録も保持し、表示する。
- 表示名が未登録なら入力欄を空欄とし、写真のメタデータから自動入力しない。名前を調べる場合は、その行のショートカットからブラウザーを開いてユーザーが入力する。
- ショートカットはIDの種別に応じたVRChatのユーザー／ワールド／グループページを、既定ブラウザーで開く。アプリ内でページから名前を取得せず、URLは有効なIDから生成する。任意URLを対応表へ登録する機能は持たせない。
- 種別はID接頭辞で判断し、IDの編集・名前からの推測は行わない。IDのない名前だけの項目は表へ追加しない。
- 表示名は日本語・多言語・絵文字に対応する1行テキスト。前後の空白を除き、内部の空白や文字列は勝手に正規化・短縮しない。改行・NUL等の制御文字は保存時にエラーとする。
- 表示名を空欄にして保存すると、そのIDの手動登録名を解除する。
- ［保存］成功時に編集表を一括保存し、対象のカテゴリ見出しへ反映する。［キャンセル］はImportを含む未保存編集を破棄する。保存失敗時に既存対応表を失わず、未保存の入力も残す。

画面には「対応表はMDBをOFFにしても残る」「写真のメタデータは変更しない」を簡潔に記載する。

## 3. 表示・分類ルール

| 有効なID | 対応表の表示名 | ID別カテゴリでの扱い |
|---|---|---|
| あり | あり | 登録された表示名を表示 |
| あり | なし／空欄 | IDのみ表示 |
| なし | あり | 無情報として末尾へ表示 |
| なし | なし | 無情報として末尾へ表示 |

- **対応表の登録名 → ID** の2段階だけとする。写真に元の名称があっても、対応表が空ならIDを表示する。以前の案の「メタデータ由来の名称へフォールバック」は廃止する。
- 有効なIDを分類キーとして維持する。表示名からIDを逆引きせず、名前しかない情報を別の写真のIDへ結び付けない。
- 同じ表示名の異なるIDは別カテゴリのまま表示する。見出しは登録名を表示し、IDは見出しのツールチップ等で確認可能にする。対応表の一覧ではIDを常時確認できる。
- 適用先は［人物ID別］［ワールド別］［グループ別］の見出し。IDなしの情報を無情報として扱うのも、この3分類での規則である。名前そのものをキーとする既存の［人物名別］や、［タグ別］［撮影者別］の分類方式は変更しない。
- サイドビューのシンプル／詳細表示と写真内の原メタデータは変更しない。検索本文・ID検索・原名称検索も維持し、今回、手動表示名による別名検索は追加しない。
- 名前を編集しても写真のカテゴリ所属・実画像数・重複表示条件は変化しない。表示更新で選択・フォーカス・未保存の写真編集を失わず、古い分類結果で保存済みの新しい表示名を上書きしない。

本仕様はStage5の名称表示規則に対するv0.5.8での変更点とする。MDBの原情報を保持する処理と、IDを正本とする分類は維持する。

## 4. 独立保存と形式

保存先はEXEと同じ場所の `IdDisplayNames.json`。MDB本体・設定・サムネイルキャッシュとは独立させる。MDBのOFF削除・破損・再構築・容量整理で対応表を削除せず、MDBの容量上限へ算入しない。

登録名はユーザー入力を正本とし、MDBの取得名では上書きしない。未登録時は空の対応表として扱う。保存は検証済み一時ファイルからの置換とし、既存ファイルを保全する。破損した対応表を空データで無断上書きせず、原名称への代替ではなくID表示を継続して読込み失敗を通知する。

保存・Import／Exportに共通のJSON形式を用いる。ExportはUTF-8・BOMなし、ImportはUTF-8のBOMあり／なしを許容する。Windows内部のUTF-16との相互変換で、日本語等のマルチバイト文字・絵文字を保持する。

```json
{
  "format": "KuniVRCPhotEditor.IdDisplayNames",
  "version": 1,
  "entries": [
    {
      "type": "group",
      "id": "grp_12345678-1234-1234-1234-123456789abc",
      "displayName": "くにひろ写真部 📷"
    }
  ]
}
```

- `type` は `person`／`world`／`group`。IDの接頭辞・UUID・種別の一致を検証する。内部のキーは種別＋IDとし、同一性判定を統一する。
- 名前だけでIDがない項目は無情報として登録せず、Import時は除外件数を通知する。名前からIDを補わない。
- IDは有効でも表示名が空の行は手動対応を保存・Exportしない。Importの空名で既存登録を削除しない。登録解除は編集画面で空欄にして［保存］する。
- JSONエスケープと直接記述した日本語、絵文字のサロゲートペアを正しく復元する。不正UTF-8／不正Unicode／不正JSON／未対応版／空でない不正ID等はエラーとして全体を適用しない。他の文字コードを推測読込みしない。
- 写真パス・認証情報・ショートカットURL・取得済み名称・MDB本体はファイルへ含めない。

## 5. Import／Export

### Import

- 選択したファイル全体を検証してから、現在の編集表へ統合する。キャンセル・解析失敗では表を変更しない。
- 新規IDまたは表示名が空の既存行には取込名を設定する。同じIDに既存の非空表示名がある場合は既存名を維持し、変更しない。Import内の同一キー・同一名は1件へまとめ、同一キー・異名の重複はエラーとする。
- 追加件数・既存維持件数・IDなし等の除外件数を簡潔に通知する。競合ごとの採用選択画面や統合プレビューは設けない。上書きしたい名称は表の表示名欄で編集する。
- 取込ファイルにない既存項目は残す。Importだけではローカルファイルへ保存せず、［保存］で一括確定する。
- MDB未登録でも有効なID・名前の組は取り込み、後日そのIDを持つ画像が登録されたときに適用する。

### Export

- 現在の編集表のうち、有効なIDと非空表示名のある対応を全件書き出す。未保存の入力・Import結果も含め、画面と出力内容を一致させる。種別ごとの出力選択は設けない。
- Exportはローカル対応表の［保存］を代行しない。Export後に［キャンセル］を押しても、書き出したファイルは削除しない。これは以前の案の「保存済み表のみExport」から、一覧をそのまま扱う方式への簡素化である。
- 保存先を選び、既存ファイルへ上書きする場合は確認する。種別・IDの一定順で書き出し、同じ内容を再Importできるようにする。保存失敗・キャンセルで未完成データを既存ファイルへ置換しない。
- 出力件数を示し、人物を含むときはユーザーIDと入力された表示名が含まれることを明示する。写真へのユーザーID保存設定は変更しない。外部サーバーへの自動送信は行わない。

## 6. 受入確認

- 3列と4ボタン、行の名前入力・空欄解除・保存／キャンセル、3種類の有効IDから生成されるページへのブラウザー起動。未登録名を原名称から自動補完しないこと。
- 登録名あり→登録名、登録名なし→IDのみ。名前だけ・IDなし→無情報。名前の一致を理由に逆引き・カテゴリ統合しないこと。同名別IDを区別できること。
- MDB OFFでの無効化と対応表保持、再度ON・再構築後の再利用、破損保全・保存失敗・原画像不変。
- 日本語・半角カナ・多言語・絵文字・JSONエスケープとBOM有無の往復、不正文字コード・版・ID・制御文字の拒否、IDなし項目の除外通知。
- Importの新規／空名補完／既存名維持／IDなし除外／重複、未掲載項目の保持、キャンセル・失敗時の一括不適用。
- Exportが未保存入力を含む編集表と一致し、空名を除き、Exportでローカル保存しないこと。空表への再Import、人物情報の通知と上書き／失敗時の保全。
- ID別3分類だけへの適用、既存検索・原メタデータ表示・他分類を維持。分類中の世代管理、重複画像の選択・サイド表示・一括操作の一意性。両テーマ・長い名前・DPI。
