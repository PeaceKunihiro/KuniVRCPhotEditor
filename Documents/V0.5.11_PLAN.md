# v0.5.11 MDB有効時の読込み遅延改善案

2026-10-20（日本時間）。基準実装v0.5.10。採用案に基づき実装。[実装・確認記録](V0.5.11_IMPLEMENTATION.md)を参照。

[調査結果](2026-10-20_RESUME_MDB_INVESTIGATION.md)／[Stage5](KuniVRCPhotEditor_Stage5.md)／[利用ガイド](USER_GUIDE.md)。

## 目的と範囲

MDBを有効にした再起動後、画面内のサムネイルが背景のMDB処理を待たされる時間を減らす。特に実設定で使用中の「MDB自動値＋ディスクキャッシュ＋ブックマーク優先」を優先する。設定UI・初期値・保存形式を変えず、既存DBとキャッシュを再利用する。

スリープ復帰後の最小化問題は今回の対象外。ディスクキャッシュ自体の全索引復元、画像のデコード、ストレージ固有の遅延も存在するため、起動待ち時間の完全消滅や改善率は約束しない。

## 採用を推奨する改修

### 1. MDB用のキャッシュ保持判定を軽量化

現在のMdbUi.cppの優先判定はDiskThumbnailCache::Get(...,false)を呼ぶ。falseは利用日時を更新しない指定で、全画素の読込み・確保・SHA-256は実行される。これを表示用Getから分離する。

- キャッシュ索引と、元画像のサイズ・更新日時を含む既存キーに基づく保持判定を追加する。判定のために画素を読み込まず、大きな画素バッファも作らない。表示用のLRU・利用日時は更新しない。
- 結果は「保持あり」「保持なし」「判定待ち」の3状態とする。索引の初期化中、クリア／再設定中、短いロックを取得できない場合は判定待ちとし、その場でPrepareや全体走査を開始・待機しない。
- 判定待ちは後で再確認する。なしとして通常優先度へ落としたり、MDBから画像を削除したりしない。再試行は通知や期限付き待機で進め、CPUを使う空回りを避ける。
- クリア・容量整理・設定変更・索引再構築との世代を確認する。外部での削除や破損により索引が一時的に古くても、影響はMDBの優先順位だけに限定する。原画像やMDB本文の正しさを索引だけで認定しない。
- 実際に画素を表示するGetは、従来のファイル構造・キー・全画素ハッシュ検証を維持する。保持判定の軽量化を破損キャッシュの表示許可には使わない。

実装箇所はDiskThumbnailCache.h/.cpp、MdbUi.cppのコールバックとMdbStore.h/.cppの結果処理が中心。キャッシュ索引の状態・ロック設計を確認してからAPI名を確定する。

### 2. 表示を優先してMDBの背景収集を進める

既存のサムネイルワーカー内では表示用が先だが、別のMDBワーカーが同時に走るため、アプリ全体の優先順位にはなっていない。MDB側の背景処理にも表示負荷を伝える。

- 画面内と既存の少量先読み範囲に未完了のサムネイルがある間は、新たな背景収集・自動優先確認を控える。表示が落ち着いたら小分けで再開する。ワーカー数を増やして競合を悪化させない。
- 表示要求の変化を安全な共有状態・通知で伝える。MDBスレッドからListView等を直接参照しない。app.mutex、MDBのcontrol/io、ディスクキャッシュのcontrol/ioをまたぐ待機やコールバックで循環待ちを作らない。
- 継続スクロール中は表示を優先するが、操作終了後に残りの収集が必ず進むようにする。失敗画像・保持予算によるプレースホルダーを「永遠に未完了」と誤認してMDBが停止しないようにする。
- 明示的なメタデータ検索・カテゴリ準備・対応表への反映は、背景の自動収集と区別して実行する。MDB OFF時の削除、設定変更、停止・終了の制御を表示待ちで妨げない。
- 起動復元・明示再読込みごとの優先更新要求を保持し、判定待ちでも消さない。フォルダーが切り替わったら古い背景の優先走査を整理し、すでに有効なMDB登録まで削除しない。処理中のOS読込みを即時中断できる保証はしない。
- 通常読込み・検索等で収集する既存仕様を維持する。画面外の全画像を常に新規登録する仕様へ拡張せず、MDB自動方式の優先判定が必要な画像の走査を分割する。

既存のScheduleThumbnails／ScheduleBookmarkPrefetchと連携し、優先確認のためにファイル一覧全体をUIタイマーごとに複写・走査しない。起動時の大きな処理を単に別のUI待ちへ移す変更にしない。

## 今回維持するもの・後段候補

- 自動方式は再読み込み時にディスクサムネイル保持画像を優先登録する。固定／自動／無制限の容量、AB_等の除外、DBの保存場所・通常終了時の保持、OFF時の通知・削除は維持。
- 原画像のサイズ・更新日時・取得可能な変更時刻／ファイルIDによるMDB変更検知、解析中の再検証、破損時の直接検索への補完を維持。
- ディスクキャッシュ全体の索引復元は依然必要。今回のMDB判定から重いGetを除くことと、ディスクキャッシュ全体の作り替えは区別する。
- DB整合性検査やFULL同期を無条件に省かない。書込みトランザクションの一括化、集計頻度の削減、キャッシュ索引の永続化は、主改修後もボトルネックとして残った場合に追加調査する。
- 同じ画像の背景要求は集約し、不要な二重収集を避ける。ただし利用日時の更新や変更確認を全て停止して高速化する案にはしない。

## 確認方法と受入条件

| 確認 | 期待する結果 |
| --- | --- |
| 保持判定単体 | 画素読込み・画素ハッシュ・画素バッファ確保が0。表示用Getの破損検出は従来どおり |
| 索引未準備／ロック競合 | 判定待ちとして戻り、準備後に再実行。取りこぼし・優先度の誤降格・空回りがない |
| 初回表示と背景処理 | 表示待ち中に次の背景処理を投入せず、表示後に背景収集が完了。スクロール停止・失敗画像・予算制限でも再開する |
| 再起動後の登録済み画像 | 変更なし画像でMDBの再利用を維持し、不要な原画像メタデータの再解析が増えない |
| 外部変更・削除・破損 | 原画像変更の検出、キャッシュ再生成、MDBの直接解析への補完を維持 |
| 状態変更 | フォルダー移動・再読込み・設定変更・MDB OFF・終了で古い要求や判定を誤適用しない。待機が停止を妨げない |
| 検索・分類・編集 | 明示操作が背景待ちで止まらず、従来の検索結果・カテゴリ・重複表示と保存保全を維持 |

性能確認はMDB OFF／ON固定／ON自動、キャッシュあり／なし、登録済み／未登録、通常／カテゴリ表示を区別する。最低限、実報告に対応する「通常表示＋登録済みMDB＋保存済みサムネイル」と、初回登録を確認する。

測定値は「一覧確定から画面内サムネイル完了」「プロセス起動から初回表示」「MDB背景処理完了」を分ける。非表示・保持上限・読込み失敗の扱いも測定条件へ記載し、以前のPython全キャッシュ走査時間を起動時間や改善倍率として再利用しない。現行版との同一データ比較を複数回行う場合は、専用ハーネスと絞った測定でウィンドウ表示の負担を抑える。OSキャッシュ非統制の比較はその限界を明記する。

受入は専用データで表示待ち中の不要な背景処理が抑制されることと、測定条件を揃えた比較で改善が確認できること。改善が確認できない条件では解消済みと表現せず、残るボトルネックを記録する。
