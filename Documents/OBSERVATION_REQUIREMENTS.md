# 観測機能・サイドビュー改修要件

更新日：2026-11-28（日本時間）。v0.6.7で実装。検証範囲は更新履歴と引継ぎを参照。

## MDB操作結果の表示

- 選択画像が切り替わったら、直前のMDB操作結果を解除し、［未実施］と表示する。
- 未選択・複数選択では、その状態に応じた選択案内を表示する。
- 処理中に選択が変わった場合は、古い画像の結果を新しい選択へ反映しない。

## サイドビューの項目選択

- 表示領域が小さくタブが収まらない場合、［◀］［▶］による移動をプルダウンによる項目選択へ変更する。
- 選択肢は［シンプル］［詳細］［OCR］［MDB］［観測］とする。
- 現在の項目名とプルダウンボタンを表示し、拡縮・表示方式切替時にも選択を維持する。

## 観測タブ

- サイドビューに［観測］を追加する。2026-11-28にユーザーが提示した「観測機能GUIイメージ.png」を配置の参考とする。
- VRChatログを基準にユーザーの入退室、移動ワールド履歴、読み込まれた動画URLを観測する。
- 項目選択の下に更新頻度の選択、その下にスクロール可能な読取り専用の記録欄を置く。
- 最新イベントを最上段に追加し、更新時は最新位置へ自動スクロールする。各イベント行に日付を表示する。v0.6.9の表示形式は下記を参照。

| 更新頻度 | 動作 |
| --- | --- |
| オフ | 観測と観測ログ保存を停止する。初期状態はオフ |
| 標準 | 10秒に1回、最新イベントを表示する |
| 高 | 2秒に1回、最新イベントを表示する |

更新間隔の間に発生したイベントも記録対象とする。表示更新の間隔をイベントの間引きに用いない。

## 保存形式

- TXTベースで保存し、**1行1イベント**とする。指定形式は各行の形式とし、ファイル名には適用しない。
- 各行は `yyMMdd-hhmmss-tag-content` の形とする。
- tagは `join`／`leave`／`world`／`movie` 等を使用する。
- contentにはイベントに応じてユーザー名とユーザーID、ワールド名とワールドID、動画URL等を記録する。
- 入退室時刻とワールド移動・動画のイベント時刻を記録する。

```text
261128-021137-join-ユーザー名&usr_…
261128-021136-leave-ユーザー名&usr_…
261128-021136-world-ワールド名&wrld_…
261128-021138-movie-https://…
```

## 観測容量

- ［キャッシュ設定］ダイアログに［観測容量］の項目を追加する。
- 初期容量は **10 MB** とする。
- 保存上限を超える場合は、**古いイベントから削除する**。ファイル単位だけの削除で新しいイベントまで失う方式は避け、保持対象をイベント単位で判断する。
- 容量を減らした場合も、適用した上限に収まるよう古いイベントから整理する。

## 実装前に確定する詳細

実装時に次の詳細を採用した。

- 文字コードはUTF-8、保存先はEXE配下のData/observation-events.txt。容量は1～1000 MB（1 MB＝100万バイト）、初期10 MB。保存時は一時ファイルから置換し、容量縮小も次の背景処理で反映する。
- 時刻はVRChatログ内のイベント時刻をローカル時刻へ変換し、hhは24時間表記とする。改行・バックスラッシュ・フィールド内の&をエスケープする。取得できない名前・IDは空欄とする。
- 表示は新しい順、保存はログの取込み順。同時刻のイベントもログ内の順序を維持する。画面表示は最新2000件・約50万文字に制限し、保存容量は別に管理する。
- 観測は写真への自動記録と独立して動作する。オフ時も表示済み記録と保存分を保持する。開始・再開時は現在ログの末尾から追跡し、停止中を遡らない。再起動時はオフ。参照先は記録設定のログフォルダー。
- 既存の入退室・ワールド解析を利用する。動画URLはvideoとloadまたはplayを含むログ行のHTTP／HTTPS URLを抽出する。実プレイヤーごとのログ互換性は未検証。ログに記録されないURLの取得は保証しない。
- ファイル識別情報と読取り位置を保持し、追記途中の行を次へ持ち越す。観測中の別ログへの切替・切詰めでは先頭から追跡する。読取り／保存エラーは観測欄上部へ表示する。保存済みイベントは再起動後に再表示する。

## 受入確認

- 初期オフ、標準10秒、高2秒、オフへの切替と保存停止。
- 入退室・ワールド・動画イベントの内容、1行1イベント、行内データの区切り。
- 最新行の上段追加、自動スクロール、行ごとの日付表示、狭い領域でのプルダウン選択。
- 初期10 MB、容量超過・容量縮小時に古いイベントから削除され、新しいイベントが保持されること。
- 選択画像切替時のMDB［未実施］表示と、遅れて届く旧画像の結果の破棄。

## v0.6.9の観測表示

画面は yyMMdd hhmmss tag content とする。日時と通常のcontentは黒。保存ファイルには既存のハイフン区切り形式を使用する。

更新頻度の右に［折り返し：ON／OFF］を置く。初期ON、設定JSONのobservationWrapで保持し、旧設定で省略されている場合もON。ONは欄幅に合わせた折り返しと続きの行の字下げ、OFFは横スクロールとする。切替時は表示位置と選択範囲を保持する。狭い欄では続きの行の字下げを幅の半分以内に抑える。

| 対象 | 色 |
| --- | --- |
| join | #0000CD |
| leave | #800000 |
| world | #006400 |
| movie・その他のtag | #000000 |
| content内のHTTP／HTTPS URL | #6495ED |
| content内のusr_形式ユーザーID | #9ACD32 |

tag文字部分と該当するcontentの範囲に着色する。URL内のユーザーIDはURL色を優先する。Rich Editを使用し、ログ欄はv0.6.11から標準は白背景、ナイトモードは黒背景とする。

## 2026-11-28 v0.6.9 ユーザー実機テスト画像

ユーザー提供の2枚の画面画像で、実VRChat使用中の観測欄にjoin／leave／world／movieが並び、日付・時刻・タグ・内容のスペース区切り、タグとURL・ユーザーIDの色分け、折り返しOFF／ONの表示と続き行の字下げを確認した。標準（10秒）が選択されている。静止画での確認のため、実更新間隔、自動スクロールのタイミング、保存ファイルの整合性、容量超過時の整理、キャッシュ設定の可変サイズは今回の確認範囲に含めない。

画面には長い動画配信URLがあり、折り返しONで多数の行を占める。複数の動画URL末尾には単一引用符が見える。URL抽出の終端判定と、長いURLの表示方法を改善候補として記録する。元ログ行と保存TXTは未照合のため、引用符の由来や同一動画に関連する複数URLの意味は未確定。画像中の人物ID・パス・具体的なURLは文書へ転記していない。
## v0.6.10の表示修正と追加検討（2026-11-28）

画面表示を hh:mm:ss tag content へ戻す。tag・URL・ユーザーIDの着色範囲も表示上の時刻の長さへ合わせる。

以下はv0.6.11で実装。

- ナイトモードのログ欄は黒背景とし、標準で黒を指定している日時・時刻・通常content・movie／otherタグの初期色を白とする。日時（日付）色は設定として保持し、現在の時刻のみの表示には時刻色を用いる。
- ［フォント］ダイアログに観測用の色設定表を置く。列は標準／ナイトモード、行は日時・時刻・通常content・URL・ユーザーID・join・leave・world・movie・otherとする。RGBの#RRGGBB形式を入力し、無効値は適用しない。色設定の変更は適用で保存、キャンセルで破棄する。
- 色設定は既存のsettings.jsonへ統合する。観測容量・折り返し等の既存設定も同じ設定ファイルで管理する。
- 外部保持フォルダーは既存Data配下へ寄せる案。観測はData/observation-events.txt、MDBとディスクサムネイルはData配下の用途別フォルダーとする。大量キャッシュ・DB・TXTは用途別ファイルで管理する。同一ドライブ内で移動し、移動前後の識別情報が一致することを検証する。競合・アクセス不可時は両方を保全して旧保存先を利用し、キャッシュ設定のタイトルへ表示する。保存先はプロセス中固定し、次回起動時に再判定する。

## 設定ファイルの配置（v0.6.12）

標準保存先はEXE配下のData/settings.json。旧EXE直下のsettings.jsonは起動時に移行し、閲覧・観測・OCR・記録設定を同じファイルで保持する。移行先が既に存在するなどの競合時は旧設定を保全して利用し、保存先統合の警告をキャッシュ設定のタイトルへ表示する。新旧を自動上書き・結合しない。Dataが重複して入れ子にならないよう、他のデータ保存先はアプリ基準フォルダーから求める。
