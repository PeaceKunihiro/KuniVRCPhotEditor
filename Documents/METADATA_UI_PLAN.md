# メタデータ表示UI改修案

検討日: 2026-10-09。以下は当初の改修案。同日にユーザー指定でv0.1.2として実装した。実装結果・検証範囲はUPDATELOG.mdのv0.1.2を参照。

## ユーザー指定

- 現在のメタデータ表示を「詳細」とし、タブ切替で表示する。
- 「シンプル」を追加し、ファイル名（拡張子込み）、容量MB、解像度、作成日時、撮影者、ワールド名、ワールドID、モデルをインデントを揃えて表示する。
- 作成日時はxmp:CreateDateを優先し、次に指定のVRChatファイル名から推測する。該当しないファイル名はファイル自体の作成日時または更新日時を使う。
- 撮影者はxmp:Author、ワールド名はvrc:WorldDisplayName、ワールドIDはvrc:WorldID。データがなければ空欄。
- モデルは被写体名の表示用の予約。現時点では空欄。

## 画面案

プレビューは共通とし、その下（下配置では横）に「シンプル」「詳細」のタブを置く。
初期表示はシンプルを提案する。タブの選択は画像を切り替えても保持する。
詳細タブは現在の基本情報・階層付きタグ・値・解析状況を引き続き表示する。
シンプルはラベル列と値列を持つ固定の2列レイアウトにする。スペースやタブ文字で揃えず、全項目の値の開始位置を同じ座標に配置する。
値は読取り専用、選択・コピー可能とし、日本語・長いファイル名・長いワールド名は折り返しと縦スクロールで全文を閲覧できるようにする。
既存の右・左・下の配置とウィンドウリサイズに対応する。

| 表示ラベル | 取得元・表示案 |
| --- | --- |
| ファイル名 | ファイル名＋拡張子。フルパスは詳細に残す |
| 容量 | バイト数÷1,000,000を小数点以下2桁で表示する案（例: 12.34 MB）。詳細は正確なバイト数を維持 |
| 解像度 | デコードした幅 × 高さ（px）。読込み失敗なら未取得として扱い、0 × 0を捏造しない |
| 作成日時 | 下記の優先順位で取得し、値に取得元を添える |
| 撮影者 | xmp:Author。欠落時は空欄 |
| ワールド名 | vrc:WorldDisplayName。欠落時は空欄 |
| ワールドID | vrc:WorldID。欠落時は空欄 |
| モデル | 空欄。将来の被写体名表示用に予約。入力・推測はしない |

## 作成日時の優先順位案

1. 読取り・解釈可能なxmp:CreateDate。
2. ファイル名（拡張子を除く）が厳密に VRChat-YYYY-MM-DD-hh-mm-ss.microSec_WidthxHight に一致する場合、その日時を使用。
3. Windowsが保持するファイルの作成日時。
4. ファイルの作成日時が取得できない場合、ファイルの更新日時。
5. いずれも取得できなければ日時の値は空欄とし、読込み状況を別途表示。

ファイル名の解析案:
- VRChat-の接頭辞と区切りを確認し、YYYY / MM / DD / hh / mm / ss、サブ秒、幅・高さを個別に検証する。
- サブ秒は1〜6桁を許容する案。幅・高さは正の整数とする。
- 月日・うるう年・時分秒が実在する日時か検証する。部分一致、末尾の余分な文字、VRChat_等の別形式を無条件に受け入れない。
- ファイル名の解像度は形式判定に使い、シンプルの解像度自体は実際の画像の幅・高さを使用する。
- 例: VRChat-2026-10-09-21-30-45.123456_1920x1080.png → 2026-10-09 21:30:45.123456（ファイル名から推測）。

取得元は「XMP」「ファイル名から推測」「ファイル作成日時」「ファイル更新日時」と表示し、撮影日時とOSのファイル日時を混同しない。
XMPのタイムゾーン情報は保持する。タイムゾーンのない値やファイル名の日時に、未確認のタイムゾーンを付け加えない。
ファイルの作成・更新日時は現PCのローカル時刻で表示する。
XMP日時が不正なら詳細にその値・解析状況を残し、次の取得元へフォールバックする。ファイル名推測で原本メタデータを書き換えない。

## 実装方針・注意点

現状のInfoは、基本情報とWICタグを1本の文字列にまとめている。
シンプル欄をその文字列から抜き出すのではなく、ファイル情報・XMPの対象項目・日時の取得元を構造体として保持し、同じ非同期結果から両タブを更新する。
現在のフォルダー世代・選択世代の検証を維持し、タブ切替のために画像を再読込みしない。

現在のWIC対応は暫定であり、対象XMPタグが取得できるかを実際のVRChat写真で確認する必要がある。
XMPの接頭辞はXML内で変更可能なため、文字列の「xmp:」「vrc:」だけで照合せず、名前空間URIとプロパティ名で識別する。
対象の名前空間URI・格納形態（属性、要素、配列など）は実ファイルで確認する。VRChatのURIやタグ別名を推測して固定しない。
xmp:Authorがない場合に別のタグを勝手に撮影者として代用しない。構造・配列の場合は確認した値の意味に合わせて全文表示する。
WICで対象XMPを取得できない場合は、PNGテキストやJPEGのXMP抽出を補完する必要があり、UI変更だけで対応完了としない。
データ欠落時の空欄と解析失敗を区別し、解析失敗は状態表示・詳細で知らせる。
モデルの元タグはまだ指定されていないため、この改修では予約欄だけを設ける。

## 確認項目

- 両タブ、右・左・下の配置、リサイズで値の開始位置が揃い、長文の全文閲覧・コピーができる。
- タブ切替・画像切替・ホイール・再読込みで別画像の情報が混在せず、タブ切替だけでは再読込みしない。
- 指定XMP4項目の実データ・欠落・接頭辞変更・日本語・不正日時を扱える。
- 日時の優先順位、うるう年、存在しない日付、サブ秒、該当しないファイル名を確認する。
- ファイル名推測・ファイル作成・更新の出所が分かる。解像度と容量は実ファイル由来である。
- 空欄の予約モデル、破損画像、読込み途中、未選択を扱える。
- v0.1.1の一覧拡縮、Ctrlホイール、フォト起動、設定互換性を維持する。

v0.1.2の実装と合成画像・非表示GUIの自動確認は完了し、UPDATELOG.mdに記録済み。実写真・新UIの目視確認と圧縮XMP対応は未完了。
